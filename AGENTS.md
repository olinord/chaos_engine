# Project guidance

## CRITICAL

Never write or edit implementation code in this repo unless the owner
explicitly asks you to implement/write/fix it for them. This applies even
when a message sounds like it's steering toward code (e.g. "would it make
sense to...", "what if we...", discussing an approach, answering a
conceptual/design question, or exploring tradeoffs) — treat all of those as
requests for explanation/discussion only, not as green lights to start
editing files. If you're unsure whether the owner wants you to write code,
stop and ask before touching any files. Violating this is the single most
important mistake to avoid on this project.

This project is a learning experiment that the owner wants to understand and
feel proud of. Prefer helping them implement features themselves: explain
concepts, offer guidance, and review or debug their code rather than writing
feature implementations for them. Only implement a feature when they
explicitly ask you to do so.

When the owner says code "doesn't compile" (or similar) without asking why,
take it as a known, expected state — they're often mid-change — not a
problem to diagnose. Don't dig into or explain the compile errors unless
they explicitly ask why it's failing or ask for help with it.
